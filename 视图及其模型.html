    4. 视图及其模型

    到目前为止，动作都是自己生成响应：文本、JSON，以及写在字符串中的少量 HTML 标签。在 MVC 应用程序中，这是视图的职责：视图是一个描述页面 HTML 的文件，其中带有占位符，用于放置动作传给它的数据——即视图模型。

    [Flask] 自带一个视图引擎 [Jinja2]，由同一个团队（*Pallets* 项目）开发。也可以使用其他引擎（[Mako]、[Chameleon]……），但 [Jinja2] 是 [Python] 中使用最广泛的：它出现在 [Django] （作为可选项）、[Ansible]、静态网站生成器等之中……本课程使用的就是它。

    [Jinja2] 视图（文档中称之为 *template*，即页面模板）是一个文本文件——这里是 HTML 文件——其中有三种标签会在服务器端被解释：

    • [{{ expression }}]：表达式的值，插入到页面中；
    • [{% instruction %}]：指令：条件（[if]）、循环（[for]）、模板继承（[extends]、[block]）、包含（[include]）、宏……；
    • [{# comment #}]：不会出现在生成页面中的注释。

    其他所有内容都原样复制。表达式的语法与 [Python] 相似。这不同于 [Thymeleaf]，即 [Spring MVC] 课程的视图引擎，其视图是添加了 [th:] 属性的有效 HTML 文件；相反，它使 [Jinja2] 更接近 [Razor] （[ASP.NET Core MVC]），后者把 HTML 和代码混合在一起。默认情况下，[Flask] 在应用程序的 [templates] 文件夹中查找视图。

    # controllers/views.py：返回视图的动作
from datetime import datetime

from flask import Blueprint, render_template

from models.page import PageModel

views = Blueprint("views", __name__)


# render_template：Jinja2 引擎根据视图
# templates/views/index.html 以及作为关键字参数传入的变量构建页面
# （这里只有一个，[model]）；生成的页面就是动作的响应
@views.get("/")
def index():
    model = PageModel(
        "My first view",
        "This page was built by Jinja2, on the server.",
        datetime.now().strftime("%H:%M:%S"))
    return render_template("views/index.html", model=model)


# 同一个视图配上另一个模型；或者另一个视图，配 404 状态码
@views.get("/hello/<name>")
def hello(name):
    if name == "unknown":
        # 元组 (page, code)：页面，以 404 状态码发送
        return render_template("views/unknown.html", name=name), 404
    model = PageModel(
        f"Hello {name}",
        "This time, the title of the page comes from the URL.",
        datetime.now().strftime("%H:%M:%S"))
    return render_template("views/index.html", model=model)
    • 第 4 行：导入函数 [render_template]；
    • 第 16–19 行：动作构建视图模型。[datetime.now().strftime("%H:%M:%S")]：格式化后的当前时间（见示例 12）；
    • 第 20 行：[render_template] 指示 [Jinja2] 生成页面：第一个参数是视图路径，相对于 [templates] 文件夹；后面的命名参数是视图的变量；这里只有一个：[model]。[render_template] 返回所生成页面的文本，它成为动作的响应（类型为 [text/html]）；
    • 第 28 行：另一个视图，带有不同的变量（[name]）。元组 [(page, 404)] 发送状态码为 404 的页面（见示例 03）：一个自定义错误页面；
    • 第 29–33 行：与动作 [index] 相同的视图，但使用不同的模型。这正是把动作与视图分离的好处：同一个视图可以被多个动作使用。

from decimal import Decimal

@basics.get("/")

    # app.py：示例 14 的应用
from flask import Flask

from controllers.basics import basics


def create_app():
    app = Flask(__name__)
    # {% ... %} 标签不会在生成的页面中留下空行：
    # trim_blocks 删除标签后面的换行符，lstrip_blocks 删除
    # 标签所在行中它之前的空格
    app.jinja_env.trim_blocks = True
    app.jinja_env.lstrip_blocks = True
    app.register_blueprint(basics)
    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)
    • 第 12–13 行：[app.jinja_env] 是应用程序的 [Jinja2] 环境——即加载并执行视图的对象。默认情况下，单独占一行的 [{% %}] 标签会把它前面的空格和后面的换行符保留在生成的页面中：循环就会产生大量空行。[trim_blocks] 会移除标签后面的换行符，而 [lstrip_blocks] 会移除标签前面的空格。这两项设置不会影响页面的显示（浏览器会忽略这些空白字符），但它们使生成的 HTML 更易读。后面所有示例都启用了这两项设置。

  <h1>{{ model.title }}</h1>

  {# 2. {{ }} 会转义 HTML；safe 过滤器则原样插入 #}
  <p>2a. {{ model.html }}</p>
  <p>2b. {{ model.html | safe }}</p>
  {# 3. 一个条件 #}
  {% if model.logged_in %}
  <p>3. You are logged in.</p>
  {% else %}
  <p>3. You are not logged in.</p>
  {% endif %}
  {# 4. 一个循环：[loop] 描述循环的状态 #}
  <p>4. Our products:</p>
  <ul>
    {% for product in model.products %}
    <li>no. {{ loop.index0 }}: {{ product.name }}, {{ product.price }} {{ model.currency }}
      {{ "(in stock)" if product.in_stock else "(sold out)" }}
      {% if loop.first %}- the first one{% endif %}
      {% if loop.last %}- the last one, seen by {{ model.name }}{% endif %}
    </li>
    {% endfor %}
  </ul>
  {# 5. 空列表：for 循环的 else 块 #}
  <p>5. Your cart:
    {% for p in model.cart %}<span>{{ p.name }}</span>{% else %}it is empty.{% endfor %}
  </p>
  {# 6. 计算表达式、set 变量，以及 format 过滤器 #}
  <p>6. {{ count }} products, for a total of {{ total }} {{ model.currency }};
    average price: {{ "%.2f" | format(total / count) }} {{ model.currency }}</p>
  {# 7. 对象内部的对象，以及 Python 方法（upper） #}
  <p>7. Address: {{ model.address.street }}, {{ model.address.city.upper() }}</p>
  <p>8. An email address: contact@example.com</p>
</body>
</html>
    • 第 9–10 行：[{% set %}] 创建一个视图变量。过滤器用于转换值：[value | filter] 或 [value | filter(parameters)]。过滤器 [sum(attribute="price")] 对列表中各元素的 [price] 属性求和；过滤器 [length] 返回列表的长度。[Jinja2] 提供了大约五十个过滤器：[upper]、[lower]、[title]、[trim]、[join]、[sort]、[round]、[default]、[replace]、[truncate]……；
    • 第 15 行：值 [None] 被显示为……[None]。过滤器 [default(value, true)] 用指定的值替换“空”值（[None]、空字符串、零）；如果没有第二个参数 [true]，它只会替换未定义的变量；
    • 第 17–18 行：[{{ }}] 会转义 HTML（2a）；而过滤器 [safe] 则声明该值是安全的 HTML，应当原样插入（2b）。[safe] 仅用于应用程序自己生成的 HTML，绝不能用于用户输入；
    • 第 20–24 行：一个条件：[{% if %}]、[{% elif %}]、[{% else %}]、[{% endif %}]。与 [Python] 用缩进来界定代码块不同，[Jinja2] 用 [end...] 标签来关闭每个代码块；
    • 第 28–34 行：一个循环 [{% for %}] …… [{% endfor %}]。在循环内部，特殊变量 [loop] 描述循环的状态：[loop.index] （迭代序号，从 1 开始）、[loop.index0] （从 0 开始）、[loop.first]、[loop.last] （分别在第一次和最后一次迭代时为真）、[loop.length] （元素个数）。循环之外的变量（[model.name]）仍然可以访问；
    • 第 30 行：[Python] 的条件表达式 [a if condition else b] 在 [Jinja2] 中同样适用；
    • 第 38 行：[for] 循环可以包含一个 [{% else %}] 块，当列表为空时执行。这比用 [if] 检查列表长度更简单；
    • 第 41–42 行：计算表达式（[total / count]）。过滤器 [format] 应用的格式类似于 [%] 运算符（来自 [Python]）：["%.2f"] 显示保留两位小数的数字。在示例 16 中，我们将看到一种格式化数字和金额的好得多的方法；
    • 第 44 行：点号表示法可以遍历对象（[model.address.city]），并允许调用它们的方法：[upper()] 是 [Python] 字符串的方法；
    • 第 45 行：一个电子邮件地址，原样书写。字符 [@]在其他视图引擎（[Razor]）中有特殊含义，但在 [Jinja2] 中没有：只有标签 [{{ }}]、[{% %}]、和 [{# #}] 会被解释。

from pathlib import Path

from flask import Blueprint, Flask, g, request

from helpers import formats
from controllers.pages import pages

BOOTSTRAP = Path(__file__).resolve().parent.parent / "common" / "bootstrap"


def create_app():
    app = Flask(__name__)
    app.jinja_env.trim_blocks = True
    app.jinja_env.lstrip_blocks = True
    app.register_blueprint(Blueprint("bootstrap", __name__, static_folder=BOOTSTRAP,
                                     static_url_path="/bootstrap"))
    app.register_blueprint(pages)

    # 每个请求的格式化语言：URL 的 ?lang=fr 参数，
    # 否则为英语。before_request：在每个动作之前
    # 执行的函数；[g]：在一次请求期间存在的对象
    @app.before_request
    def set_language():
        g.locale = "fr_FR" if request.args.get("lang") == "fr" else "en_US"

    # "自制" 过滤器：{{ price | money }}、{{ day | long_date }}
    app.add_template_filter(formats.money)
    app.add_template_filter(formats.long_date)
    # 一个全局函数，可在所有视图中调用：{{ uppercase(name) }}
    app.add_template_global(formats.uppercase)
    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)
    • 第 23–25 行：格式化所用的语言取决于请求：URL 的参数 [?lang=fr] 选择法语；英语是默认语言。[@app.before_request] 注册一个函数，[Flask] 会在每个动作之前执行它（请求生命周期一章将详细介绍这些“钩子”）。它把区域设置存放在 [g] 中，这是 [Flask] 的一个对象，与 [request] 一样，它专属于当前请求：你可以往里面存放任何东西（[g.locale = ...]）；请求结束时它会被丢弃。这是在处理同一个请求的不同函数之间共享信息的方式，无需把信息作为参数一个接一个地传递。数据作用域一章将再次讨论这一主题；

# 两个装饰器：同一个动作对应两条路由
@books.get("/")
@books.get("/search")
def search():
    keyword = request.args.get("keyword", "")
    genre = request.args.get("genre", "")
    word = keyword.strip().lower()
    results = [book for book in BOOKS
               if (not word or word in book.title.lower() or word in book.author.lower())
               and (not genre or book.genre == genre)]
    return render_template("books/search.html",

# 这里是去除输入两端的空格
def clean(value):

    # 整数字段中输入 "abc"）

    4.8. 示例 20：Post/Redirect/Get 模式

    当 POST 动作以一个页面作为响应时，该页面是 POST 的结果。如果用户重新加载页面（按下 [F5]），浏览器会再次发送 POST 请求，并在此之前显示一条几乎没人会读的警告：命令被发送了两次，消息也被发布了两次。Post/Redirect/Get 模式（PRG）避免了这个问题：成功的 POST 动作不返回页面；它以一个重定向（示例 04）作为响应，指向一个 GET 页面，浏览器会立即请求该页面。重新加载这个页面只会重新执行 GET 动作。

    还有一个问题：GET 页面想要显示一条消息（“任务已添加”），但知道这条消息的是 POST 动作，而它无法向尚未发生的请求传递变量。解决方案是：闪现消息，由 POST 动作发布，保留到下一个请求，显示之后即被丢弃。

from dataclasses import dataclass, replace
from threading import Lock

from flask import current_app


# 一个联系人：标识符、姓名、电话号码
@dataclass(frozen=True)
class Contact:
    id: int
    name: str
    phone: str


class ContactsService:

    def __init__(self):
        self._contacts = [
            Contact(1, "Marie Durand", "01 23 45 67 89"),
            Contact(2, "Paul Martin", "06 12 34 56 78"),
            Contact(3, "Philippe Jandot", "02 98 76 54 32"),
        ]
        self._last_id = 3
        self._lock = Lock()

    def list(self) -> list[Contact]:
        with self._lock:
            return list(self._contacts)

    # 该联系人，如果不存在则为 None
    def read(self, id: int) -> Contact | None:
        with self._lock:
            return next((c for c in self._contacts if c.id == id), None)

    def edit(self, id: int, name: str, phone: str) -> Contact | None:
        with self._lock:
            for i, contact in enumerate(self._contacts):
                if contact.id == id:
                    # 联系人是不可变的（frozen）：replace 构建一个
                    # 新的联系人，用它替换列表中的旧联系人
                    self._contacts[i] = replace(contact, name=name, phone=phone)
                    return self._contacts[i]
            return None

    def add(self, name: str, phone: str) -> Contact:
        with self._lock:
            self._last_id += 1
            contact = Contact(self._last_id, name, phone)
            self._contacts.append(contact)
            return contact

    def delete(self, id: int) -> Contact | None:
        with self._lock:
            contact = next((c for c in self._contacts if c.id == id), None)
            if contact is not None:
                self._contacts.remove(contact)
            return contact


def contacts_service() -> ContactsService:
    return current_app.extensions["contacts"]

    // 对带有 data-confirmation="..." 属性的表单进行确认
// 没有 JavaScript 时，这些表单会直接发送，不经确认。
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // 用户确认后要发送的表单

  // 1. 我们拦截需要确认的表单的提交
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // 提交被挂起
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // 出现窗口
    });
  });

  // 2. 窗口的两个按钮
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // 提交，不再次触发 'submit' 事件
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • 第 3 行：代码被包裹在一个立即执行的匿名函数中；它的变量不会与页面上其他脚本的变量相互干扰；
    • 第 4–6 行：窗口、消息位置，以及等待确认的表单；
    • 第 9–14 行：对于每个带有 [data-confirmation] 属性的表单，拦截 [submit] 事件——即表单提交时触发的事件。[preventDefault()] 暂停提交；表单被搁置，其消息（[dataset.confirmation]，即 [data-confirmation] 属性的值）显示在窗口中，窗口随即出现；
    • 第 19–25 行：窗口中点击事件的单一处理器：[event.target] 是被点击的元素；它的 [data-action] 属性指明是哪个按钮。“Yes”使用 [submit()] 方法提交待处理的表单，该方法与点击按钮不同，不会触发 [submit] 事件（否则窗口会再次出现）；“No”则隐藏窗口。

    没有 [JavaScript] 时，表单只是不经确认直接提交：页面仍然可用。这就是渐进增强：[JavaScript] 增添了便利，但应用程序并不依赖它。
