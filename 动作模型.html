    3. 动作模型

    动作需要浏览器发送的信息：URL 的参数（[?name=martin&age=42]）、表单字段、JSON 请求正文，有时还有一个 HTTP 请求头。原课程把所有这些信息称为 动作模型。本章展示动作如何获取这些信息、将其转换为正确的类型并进行验证。这一过程称为数据绑定。

    [Flask] 在这方面比其他框架极简得多：它提供对请求信息的访问，以字符串的形式，仅此而已。将 ["42"] 转换为整数 42、验证名称至少有两个字符、把各字段组装成对象——这一切都由应用程序负责。我们将先手工完成这些工作（示例 07），然后使用 [Pydantic] 库（示例 08–12），它用一个类来描述模型，类中的每个字段都指定其类型和约束。在下一章中，HTML 表单将由另一个专为它们设计的库 [WTForms] 来处理；[Pydantic] 仍然是处理 URL 参数和 API 的 JSON 正文的自然工具。

    术语说明：在下一章中，“模型”一词将主要指动作传递给其 视图的数据。本章中所说的动作的模型，则是它所 接收的数据。

    示例 07 至 12 的运行方式与上一章的示例相同：在示例目录中打开终端，并激活虚拟环境（[python app.py]）；[Ctrl-C] 可停止服务器。它们的 [app.py] 文件都很相似：一个工厂 [create_app] 负责创建应用程序，配置 JSON 提供者（保留重音符号，键保持原有顺序；参见示例 03），并注册一个蓝图。只有当它们引入新内容时，我们才会加以评注。

    # controllers/parameters.py：URL 的参数（"查询字符串"）
from flask import Blueprint, abort, request

parameters = Blueprint("parameters", __name__, url_prefix="/parameters")


# /parameters/action01?name=martin：request.args 包含 URL 的参数；
# get 返回参数的值，参数缺失时返回 None
@parameters.get("/action01")
def action01():
    name = request.args.get("name")
    return f"name = [{name}], of type {type(name).__name__}"


# /parameters/action02?age=42：type=int 将值（字符串）转换为
# 整数；参数缺失或不是整数时，结果为 None
@parameters.get("/action02")
def action02():
    age = request.args.get("age", type=int)
    return f"age = [{age}], of type {type(age).__name__}"


# /parameters/action03?age=42：必需的参数；参数缺失，或
# 值不是整数时，动作以 400 响应（Bad Request）终止
@parameters.get("/action03")
def action03():
    text = request.args.get("age")
    if text is None:
        # abort 抛出一个异常，Flask 将其转换为错误响应
        abort(400, "the [age] parameter is required")
    # 转换由我们自己负责
    try:
        age = int(text)
    except ValueError:
        abort(400, f"[{text}] is not an integer")
    return f"age = [{age}], of type {type(age).__name__}"


# /parameters/action04?page=2：参数缺失时使用默认值
@parameters.get("/action04")
def action04():
    page = request.args.get("page", default=1, type=int)
    return f"page = [{page}]"


# /parameters/action05?q=flask：URL 参数的名称不一定
# 与 Python 变量的名称相同
@parameters.get("/action05")
def action05():
    search = request.args.get("q")
    return f"search = [{search}]"


# /parameters/action06?name=martin&age=42：以字典形式一次获取所有参数
@parameters.get("/action06")
def action06():
    return request.args.to_dict()
    • 第 11 行：[request.args] 包含 URL 的参数，这些参数已经由 [Werkzeug] 解码。它是一个特殊的 字典，即 [MultiDict]，正如我们将在示例 10 中看到的，它的每个键可以接受多个值。它的方法 [get] 返回参数的值，如果参数不存在则返回 [None] 。与 [request.args["name"]] 不同，后者在参数缺失时会抛出异常，[get] 永远不会引发错误；
    • 第 12 行：动作显示该值及其类型：[type(x)] 是 [x] 的类，而 [__name__] 是 该类的名称。从 URL 获取的值始终是字符串（[str]）；
    • 第 19 行：参数 [type] 属于 [get] ，它指定一个应用于字符串的转换函数：这里是 [int]，即整数类，调用 [int("42")] 会返回 42。如果转换失败（[int("abc")] 会引发 [ValueError]），[get] 返回 [None]，就像参数缺失时一样：动作无法区分这两种情况，输入错误就这样被忽略了；
    • 第 26–35 行：一个 必需参数，以及一种能够区分两种可能错误的手动转换。[abort(400, message)] 以 400 响应（*Bad Request*——请求无效）终止动作，并附带该消息（参见示例 03）。语句 [try] / [except ValueError] 捕获 [int] 抛出的异常；
    • 第 42 行：一个 默认值，在参数缺失（或其转换失败）时使用。这是列表页码的典型用法；
    • 第 50 行：不必让 [Python] 变量与 URL 参数同名。搜索引擎常用简短的参数 [q] （*query*）；
    • 第 57 行：[to_dict()] 将 [MultiDict] 转换为标准的 [Python] 字典（只保留每个参数的第一个值），动作直接返回它：[Flask] 会把它转换为 JSON（参见示例 03）。

    3.2. 示例 08：用类描述的动作模型

    [Pydantic] 是 [Python] 中使用最广泛的数据验证库（它是 [FastAPI] 框架的核心）。它用一个类来描述所期望的数据：每个属性都有一个类型，还可以有约束。[Pydantic] 负责把接收到的数据转换为这些类型，并验证约束。它安装在示例的虚拟环境中（文件 [requirements.txt]）。

    # models/person.py：动作的模型，一个 Pydantic 类，其中每个
# 字段都带有自己的类型和约束
from typing import Annotated, Literal

from pydantic import BaseModel, ConfigDict, EmailStr, Field


class PersonModel(BaseModel):
    # 接收到的字符串会去除两端的空格
    model_config = ConfigDict(str_strip_whitespace=True)

    # 必填（无默认值），长度 2 到 20 个字符
    name: Annotated[str, Field(min_length=2, max_length=20)]
    # 整数（"42" 会被转换为 42），范围 0 到 150
    age: Annotated[int, Field(ge=0, le=150)]
    # 仅限这三个值之一
    title: Literal["Mr", "Mme", "Melle"]
    # 可选（默认为 None）；如果提供，必须是有效的电子邮件地址
    email: EmailStr | None = None
    • 第 8 行：一个 [Pydantic] 模型是一个继承自 [BaseModel] 的类。它的属性在类级别声明，并带有类型，就像 [dataclass] （示例 06）中一样；
    • 第 10 行：模型的配置。[str_strip_whitespace=True] 会去掉接收到的字符串两侧的空格：输入为 [" martin "] 的名字在验证之前会变成 ["martin"] 。属性 [model_config] 不是模型中的字段：[Pydantic] 能识别这个保留名称；
    • 第 13 行：字段 [name]。[Annotated[str, Field(...)]] 读作“类型 [str]，由 [Field(...)] 注解”。[Annotated]，来自标准模块 [typing]，它允许给类型附加额外信息——这些信息会被 [Python] 忽略，但会被各个库读取：这里是 [Pydantic] 的约束，长度为 2 到 20 个字符（[min_length]，[max_length]）。该字段没有默认值：它是 必需的；
    • 第 15 行：类型 [int]：[Pydantic] 把字符串 ["42"] 转换为整数 42，并拒绝 ["abc"]。约束 [ge] （*greater or equal*，大于或等于）和 [le] （*less or equal*，小于或等于）限制取值范围。另外还有用于严格不等式的 [gt] 和 [lt] ；
    • 第 17 行：[Literal["Mr", "Mme", "Melle"]] 是所列三个值（且只有这三个值）的类型；
    • 第 19 行：[EmailStr] 是电子邮件地址的类型；[Pydantic] 使用 [email-validator] 库（它也由 [requirements.txt] 安装）验证其语法。[EmailStr | None]：一个地址，或者 [None]。默认值 [= None] 使该字段成为 可选的。

    该模型描述所期望的数据；它不包含任何验证指令。这被称为声明式风格。

    # controllers/persons.py：以 Pydantic 类为模型的动作
from flask import Blueprint, request

from models.person import PersonModel

persons = Blueprint("persons", __name__, url_prefix="/persons")


# /persons/action01?name=martin&age=42&title=Mr
# model_validate：Pydantic 根据参数字典创建对象
# （绑定：将字符串转换为每个字段的类型），然后检查
# 约束（验证）。无效的模型会抛出 ValidationError，
# 由 app.py 转换为 400 响应：动作到此终止
@persons.get("/action01")
def action01():
    person = PersonModel.model_validate(request.args.to_dict())
    return {
        # model_dump：以字典形式表示的对象（可序列化为 JSON）
        "person": person.model_dump(),
        "ageType": type(person.age).__name__,
    }
    • 第 16 行：[model_validate] 类方法根据一个字典创建 [PersonModel] 对象——这里是包含 URL 参数的那个字典。它按以下顺序执行两个操作： - 绑定：字典中的每个值在转换为字段的类型之后，被赋给同名字段（["42"] → 42）； - 验证：检查每个字段的约束（长度、范围、允许的值等）。
    • 如果其中任一步骤失败，[model_validate] 就会抛出 [ValidationError] 异常，其中包含 所有 错误的列表（而不只是第一个）。动作不处理它：动作就此停止；我们稍后会看到由谁来处理；
    • 第 19 行：[model_dump()] 以字典形式返回该对象，[Flask] 可以把它转换为 JSON；
    • 第 20 行：年龄的类型，用来表明转换确实发生了。

    # app.py：示例 08 的应用
from flask import Flask
from pydantic import ValidationError

from controllers.persons import persons


def create_app():
    app = Flask(__name__)
    # JSON：保留重音，键保持原来的顺序（见示例 03）
    app.json.ensure_ascii = False
    app.json.sort_keys = False
    app.register_blueprint(persons)

    # 无效的模型：Pydantic 的 ValidationError 异常会在
    # 整个应用范围内变成 400 响应，并详细列出各项错误
    @app.errorhandler(ValidationError)
    def invalid_model(e: ValidationError):
        errors = [{"field": ".".join(str(x) for x in err["loc"]), "message": err["msg"]}
                  for err in e.errors()]
        return {"status": 400, "errors": errors}, 400

    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)
    • 第 17–21 行：装饰器 [@app.errorhandler(ValidationError)] 注册了一个 异常处理程序：当某个动作抛出 [ValidationError] （或其派生类的异常）时，[Flask] 会调用这个函数，把该异常作为参数传给它，并把它的返回值作为响应返回。处理程序声明在应用程序级别，因此适用于 所有 动作：每个验证模型的动作都能从中受益，而无需编写任何一行错误处理代码；
    • 第 19 行：[e.errors()] 返回错误列表。每个错误都是一个字典；我们保留两项信息：[loc] （*location*，位置），即出错的字段，形式为元组（[("name",)]；更长的元组见示例 10），以及 [msg]，即消息。表达式 [[... for err in e.errors()]] 是一个 列表推导式：它把左边的表达式应用于每个元素来构造列表；
    • 第 21 行：一个元组 [(body, code)] （参见示例 03）：一个被转换为 JSON 的字典，以及代码 400。

    # models/messages.py：验证错误的消息，英文。
# 每个 Pydantic 错误都是一个字典：它的类型（"missing"、
# "string_too_short"……）、涉及的字段（loc）、英文消息（msg），
# 以及上下文（ctx）：约束的值（{"min_length": 2}……）
MESSAGES = {
    "missing": "the field is required",
    "string_too_short": "{min_length} character(s) at least",
    "string_too_long": "{max_length} character(s) at most",
    "int_parsing": "an integer is expected",
    "greater_than_equal": "the value must be greater than or equal to {ge}",
    "less_than_equal": "the value must be less than or equal to {le}",
    "literal_error": "unknown value",
    "value_error": "invalid value",
    "too_short": "{min_length} item(s) at least",
}


# 字段名：loc 是一个元组，如 ("name",)，或 ("color", 1) 表示列表的
# 第 2 项
def field(error: dict) -> str:
    return ".".join(str(x) for x in error["loc"])


# 我们自己的消息；未知的错误类型保留 Pydantic 的消息
def message_en(error: dict) -> str:
    template = MESSAGES.get(error["type"])
    if template is None:
        return error["msg"]
    # format 用上下文中的值替换 {min_length}……
    return template.format(**error.get("ctx", {}))
    • 第 5–14 行：[Pydantic] 中的每个错误都有一个 类型 和唯一标识符（["missing"] 表示缺失字段，["string_too_short"] 表示过短的字符串，等等），与英文消息无关。[MESSAGES] 字典为每种类型关联了我们自己的消息。其中一些包含诸如 [{min_length}]、[{ge}]……之类的标记：[Pydantic] 的文档为每种错误类型提供了其 上下文的值；
    • 第 20–21 行：引发错误的字段名称，取自元组 [loc]。[".".join(...)] 把元组的元素（已转换为字符串）用句点连接起来；
    • 第 25–30 行：我们自己的错误消息。[MESSAGES.get(...)] 对于字典中找不到的错误类型，返回 [None] ；此时使用来自 [Pydantic] 的英文消息。否则，[format] 会把消息中每一处 [{name}] 替换为上下文中同名的值：["{min_length} character(s) at least".format(min_length=2)] 得到 ["2 character(s) at least"]。记法 [**dictionary] 把字典的各项作为命名参数传入；[error.get("ctx", {})] 对于没有上下文的错误会返回一个空字典。

    这种技术（根据错误类型进行翻译）正是案例研究中使用的方法：那里的消息由 键标识，这些键会被翻译成用户的语言。

from flask import Blueprint, request
from markupsafe import escape
from pydantic import ValidationError

from models.messages import field, message_en
from models.person import PersonModel

persons = Blueprint("persons", __name__, url_prefix="/persons")


@persons.get("/action01")
def action01():
    try:
        person = PersonModel.model_validate(request.args.to_dict())
    except ValidationError as e:
        # 按字段列出的错误：e.errors() 给出它们的列表

    • 第 14–19 行：动作本身在 [try] / [except] 块中拦截 [ValidationError]。如果发生错误，它会构造一个 HTML 错误列表（[<ul>]，每个错误对应一个 [<li>] 标签）；
    • 第 22 行：如果成功，则返回欢迎消息。名字要经过 [escape] 函数处理，该函数来自 [markupsafe] 库（随 [Flask] 一起安装）。[escape] 会把在 HTML 中有特殊含义的字符（[<]、[>]、[&]、["]、[']）替换为它们的 实体 （[&lt;]、[&gt;]……）：它们将被原样显示，而不会被解释。如果没有这一防范措施，用户就可以输入包含 HTML 甚至 [JavaScript] 的“名字”，这些代码会在任何查看该页面的人的浏览器中执行。这是 Web 上最常见的安全漏洞：脚本注入 （*XSS*，*cross-site scripting*）。标题和年龄不需要这种保护：它们的值已经由模型验证过（三个允许值之一，或一个整数）。在下一章中，[Jinja2] 视图引擎会对插入页面的任何值 自动 执行这种转义。

    # binding/date_fr.py：URL 路径中的法式日期 "23-09-2026"
from datetime import date, datetime

from werkzeug.routing import BaseConverter, ValidationError


# 一个 Werkzeug 转换器（Flask 所基于的库）：
# 它判断路径的某一段是否合适，并将其转换为 Python 对象
class DateFrConverter(BaseConverter):
    # 路径片段的正则表达式：dd-mm-yyyy
    regex = r"\d{2}-\d{2}-\d{4}"

    # 路径文本 -> date 对象
    def to_python(self, value: str) -> date:
        try:
            # strptime 检查该日期是否存在："31-02-2026" 会被拒绝
            return datetime.strptime(value, "%d-%m-%Y").date()
        except ValueError:
            # 路由不匹配：Flask 会查找另一条路由，然后返回 404
            raise ValidationError()

    # date 对象 -> 路径文本（由 url_for 使用）
    def to_url(self, value: date) -> str:
        return value.strftime("%d-%m-%Y")
    • 第 9 行：转换器是继承自 [BaseConverter] 的类；
    • 第 11 行：属性 [regex] 是一个 正则表达式 ，描述被接受的路径段的格式：[\d] 表示一个数字，[{2}] 表示前一个元素重复——这里是两位数字。字符串前的前缀 [r] （*raw string*，原始字符串）可防止 [Python] 解释 [\]。路由只会尝试对这种形式的路径段使用该转换器；
    • 第 14–20 行：[to_python] 把路径文本转换为 [Python] 对象，这里是 [date]。[datetime.strptime] （*string parse time*）按照特定格式解析字符串：[%d] 表示日，[%m] 表示月，[%Y] 表示四位数的年份；[.date()] 只保留日期而不含时间。[strptime] 会验证该日期是否存在：[31-02-2026] 格式正确，但会引发 [ValueError]。随后，转换器会引发 来自 [Werkzeug] 的 [ValidationError] 异常 （不要与 [Pydantic] 中的同名异常混淆）：对于路由而言，该路由与 URL 不匹配，因此如果没有其他路由匹配，就会导致 404 错误；
    • 第 23–24 行：反向操作，由 [url_for] 用来根据日期构造 URL。[strftime] （*string format time*）用于格式化日期。

    3.6.2. 由装饰器提供的参数：binding/language.py

    # binding/language.py：一个为动作提供参数的装饰器
from functools import wraps

from flask import request


# 放在动作上的 @with_language 会向它传入 [language] 参数，该参数读取自
# 头部 "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
def with_language(action):
    # wraps：生成的函数保留动作的名称（Flask 用它
    # 来命名路由）
    @wraps(action)
    def action_with_language(*args, **kwargs):
        # request.accept_languages：Werkzeug 已解析好的头部；
        # best_match：在提供的语言中，浏览器最偏好的语言
        kwargs["language"] = request.accept_languages.best_match(["fr", "en"], default="fr")
        return action(*args, **kwargs)

    return action_with_language
    • 第 9 行：装饰器是一个函数，它接受一个函数（这里是动作）并返回另一个函数（参见示例 01）。在 [def hello(...)] 上方写 [@with_language] ，等价于在定义之后写 [hello = with_language(hello)]；
    • 第 13 行：将取代该动作的函数。[*args] 以元组形式接收位置参数，而 [**kwargs] （*keyword arguments*）以字典形式接收命名参数。[Flask] 就是这样传递路径变量的（[id=3]）：该函数无需事先知道它们就能接收到它们；
    • 第 16 行：增加了一个命名参数 [language]。[request.accept_languages] 是请求头 [Accept-Language]，它已由 [Werkzeug] 解析。浏览器在这里按偏好顺序给出用户的语言：[fr-FR,fr;q=0.9,en;q=0.8] （系数 [q] 表示偏好程度，取值范围为 0 到 1）。[best_match] 从应用程序提供的语言中选出用户最偏好的那一种；如果没有合适的语言，则返回值 [default] ；
    • 第 17 行：以收到的参数和新增的参数调用原始动作。这一次，记法 [*args] 和 [**kwargs] 用于把元组和字典解包为参数；
    • 第 12 行：函数 [action_with_language] 获取动作的名称（[__name__]）和文档。这在这里至关重要：[Flask] 以每个路由所对应函数的名称来命名该路由（即 [url_for("examples.hello")] 中的 [hello]），如果有两个动作使用了该装饰器，它将拒绝注册两个同名的路由 [action_with_language]。

    我们在整个课程中都会用到这种方法：身份验证一章中的 [@login_required] 和 [@role_required] 装饰器也是以同样的方式构建的。

    # binding/types.py：用于 Pydantic 模型的 "自制" 类型
from datetime import date, datetime
from typing import Annotated

from pydantic import AfterValidator, BeforeValidator


# 一个 "自制" 约束：字符串不得包含空格。
# 函数接收已经转换为 str 的值；它返回该值，或抛出
# ValueError，其消息即为验证错误的消息
def no_space(value: str) -> str:
    if " " in value:
        raise ValueError("the field must not contain a space")
    return value


# Annotated：str 类型，外加一个在转换之后执行的
# 检查。NoSpace 随后像普通类型一样使用
NoSpace = Annotated[str, AfterValidator(no_space)]


# 一个 "自制" 转换："23/09/2026" -> date(2026, 9, 23)，在
# date 类型的验证之前执行
def date_fr(value):
    if isinstance(value, str):
        try:
            return datetime.strptime(value, "%d/%m/%Y").date()
        except ValueError:
            raise ValueError(f"[{value}] is not a valid dd/mm/yyyy date")
    return value


DateFr = Annotated[date, BeforeValidator(date_fr)]
    • 第 11–14 行：一个验证函数：它接收字段的值，如果有效则原样返回，否则抛出 [ValueError] 。异常消息就是验证错误消息；
    • 第 19 行：类型 [NoSpace] 就是类型 [str]，并以 [AfterValidator(no_space)] 进行注解：[Pydantic] 会在验证（必要时转换）该值为 [str] 之后调用该函数。这样，我们只需定义一次，就可以像普通类型一样在所有模型中重复使用这个类型；
    • 第 24–30 行：一个转换函数。***[date] 类型在 *[Pydantic] 中接受国际格式的字符串，如 ***[2026-09-23]；而我们想要法式格式，如 ***[23/09/2026]。该函数接收原始值：如果它是字符串，就把它转换为 [date]；任何其他值（例如已构造好的 [date]**）则原样返回；
    • 第 33 行：[BeforeValidator]：该函数在 [date] 类型验证之前被调用，因此验证时收到的是已构造好的 [date]。

from datetime import date

from flask import Blueprint, request, url_for
from pydantic import BaseModel, ValidationError

from binding.language import with_language
from binding.types import DateFr, NoSpace

examples = Blueprint("examples", __name__, url_prefix="/examples")


# /examples/schedule/23-09-2026：自定义路径转换器（见 app.py）
@examples.get("/schedule/<datefr:day>")
def schedule(day: date):
    # url_for 使用转换器的 to_url 方法：date -> "23-09-2026"
    return f"schedule for the day [{day}], of type {type(day).__name__}, " \
           f"URL: {url_for('examples.schedule', day=day)}"


# /examples/hello：一个并非来自 URL 而是来自头部的参数，
# 由 @with_language 装饰器提供
@examples.get("/hello")
@with_language
def hello(language: str):
    return "Hello!" if language == "en" else "Bonjour !"


# 搜索的模型：两个 "自制" 类型
class SearchModel(BaseModel):
    keyword: NoSpace | None = None
    since: DateFr | None = None


# /examples/search?keyword=flask&since=01/09/2026
@examples.get("/search")
def search():
    model = SearchModel.model_validate(request.args.to_dict())
    return f"search for [{model.keyword}] since [{model.since}]"


# 错误处理
# 蓝图的 errorhandler：将其某个动作抛出的异常转换为
# 响应（应用上的同一装饰器则适用于所有动作）
@examples.errorhandler(ValidationError)
def validation(e: ValidationError):
    # 第一个错误的消息，不带 Pydantic 的 "Value error, " 前缀
    message = e.errors()[0]["msg"].removeprefix("Value error, ")
    return message, 400, {"Content-Type": "text/plain; charset=utf-8"}
    • 第 14–18 行：路径变量 [day] 使用转换器 [datefr]：动作接收到的是一个 [date]。[url_for] 借助转换器的 [to_url] 方法，根据该日期为这同一个动作构造 URL。行尾的 [\] 分隔符表示指令在下一行继续；两个相邻的字面字符串会被拼接；
    • 第 23–25 行：装饰器的顺序很重要。它们自下而上依次应用：[@with_language] 先转换动作，然后 [@examples.get] 将转换后的函数注册到蓝图中。如果顺序相反，蓝图注册的将是原始动作，参数 [language] 也就永远不会被提供；
    • 第 30–32 行：一个模型，它把这两个“自定义”类型当作普通类型来使用。两个字段都是可选的；
    • 第 45–49 行：一个异常处理器，这次声明在蓝图上：它只处理由该蓝图的动作抛出的异常。[removeprefix] 从消息中移除前缀 ["Value error, "]，该前缀是 [Pydantic] 添加到 [ValueError] 消息中的。响应是一个由三个元素组成的元组：响应体、状态码和一个头部字典（见示例 03），这里用于纯文本响应。

    3.6.6. 结论

    让我们总结一下动作获取其模型所能使用的方法：

    来源
    方法
    路径变量
    动作的参数，由转换器指定类型（[<int:id>]、[<datefr:day>]）
    URL 参数
    [request.args]：[get] （连同 [type] 和 [default]）、[getlist]、[to_dict]
    POST 表单中的字段
    [request.form]，一个 [MultiDict]，与 [request.args] 类似
    JSON 请求体
    [request.get_json()]
    头部
    [request.headers]，以及已经解析好的对象，例如 [request.accept_languages]
    转换与验证
    一个 [Pydantic] 模型：[model_validate]、[ValidationError]、[e.errors()]
    常见错误
    [@app.errorhandler] （整个应用程序）或 [@blueprint.errorhandler] （某个蓝图）
    计算得到的参数
    一个为动作添加命名参数的装饰器

    另一方面，HTML 表单需要的不仅仅是验证：它们必须被显示出来，带着用户的输入和可能的错误重新显示，并受到保护以防伪造请求。这将是 [WTForms] 的职责，待引入视图之后，在下一章中讲解。
